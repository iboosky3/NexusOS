# Nexus PRD 写作工作区使用指南

## 当前可用范围

工作区用于单用户或受保护的个人虚拟机：需求简报、Markdown/TXT 材料、真实模型生成、结构化评审、手动编辑、反馈修订、SQLite 持久化、版本恢复以及 Markdown/HTML 导出。当前没有用户认证和租户隔离，请勿将此工作区作为多用户公共服务部署。

首次使用先阅读 [NexusOS 自身 PRD 草稿](product-prd.md)。它是依据原始需求和代码整理的产品文档，可导入工作区继续修订；不代表已经完成真实模型质量验收。

## 启动

在仓库根目录执行：

```bash
source .venv/bin/activate
pip install -e '.[dev,api,runtime]'

# 按实际服务设置，密钥仅在 API 服务配置。
export NEXUS_MODEL_NAME='你的模型名称'
export NEXUS_MODEL_BASE_URL='你的兼容模型服务地址/v1'
export NEXUS_MODEL_API_KEY='你的模型密钥'

export NEXUS_PRD_DATABASE='./data/prd.sqlite3'

python -m uvicorn nexusos.api:create_app --factory --host 127.0.0.1 --port 8000
```

在另一个终端：

```bash
cd apps/studio
npm ci
NEXUS_API_URL=http://127.0.0.1:8000 npm run dev -- --hostname 127.0.0.1
```

打开 `http://127.0.0.1:3000`，点击“编写 PRD”在新标签页打开 `/prd-studio`，也可直接访问该路径。Studio 通过同源 `/api/prd/*` 转发请求，模型密钥不会进入浏览器。旧版 `/prd` 保留供对照使用，共享同一个文档库；可从“帮助”菜单打开旧版。

环境变量也可以通过进程管理器设置。仅创建根目录 `.env` 不会自动加载到直接启动的 Python 进程；Docker Compose 的 `env_file` 才会读取它。Studio 的 `.env.local` 可保存 `NEXUS_API_URL`，不要在其中放模型密钥。

不配置模型仍然可以导入、编辑、保存和导出。点击生成会得到明确配置提示，不会退回固定模板。当前适配器调用兼容的 Chat Completions 服务，发送 `temperature` 和 `max_tokens`；服务必须支持这些参数。各供应商特定的推理参数、独立 Responses 协议、非兼容 Anthropic 接口仍需独立适配。

`NEXUS_MODEL_NAME` 只表示选定模型，并不证明服务已经可达。连接失败、限流、认证错误或非法响应会在任务记录中显示失败。PRD 工作流对所有模型统一分段生成正文；单段达到服务商输出上限时会从截断处自动续写并合并，因此不需要配置 PRD Token 上限。模型响应通过流式接口逐步显示。输入材料超过模型自身上下文窗口时仍需精简材料。

## 写作流程

1. 首页只选择工具，不传入原始想法。新版始终从空白需求简报开始；打开已有文档时使用 URL 的 `id`。
2. 在中间填写产品名称、构想、用户、问题、首版范围、约束和验收期待，也可在右侧 AI 对话区逐步澄清。AI 返回字段建议，点击“应用建议”才修改简报；不会自动保存。建议涉及的字段如已被手动修改，会要求重新提问，避免覆盖。保存至少需要产品名称；启动生成还需产品构想。其余缺失信息会标记待确认，填写进度不代表质量评分。
3. 添加资料。支持 `.md`、`.txt`、`.markdown` 或粘贴原文；每份提供来源名称。仅有 URL 不会自动抓取网页。
4. 在“原型设计”中生成或导入原型，核对并确认截图，再从顶部“运行”菜单启动 PRD 编写。需求、体验、技术、写作、评审阶段实际运行并记录所选 Agent 和 Skill；当前阶段的模型正文会实时显示。
5. 阅读 PRD 与问题清单，特别检查“建议”“假设”和“待确认”。没有问题也只代表等待人工评审。
6. 在正文中直接编辑，或填写修改要求后修订。修订会先保存当前人工修改，再生成一个新版本。
7. 需要时只重新评审，避免重复写作。修改正文或简报后，旧评审不再作为当前评审显示。
8. 导出当前正文为 Markdown 或 HTML。HTML 可离线阅读；导出不等同于服务器保存。

导入已有 PRD：从“文件”菜单选择“导入 Markdown 文档”，或进入空白 `PRD.md` 页签导入。已有正文时请新建文档导入，或自行在编辑模式合并，避免无提示覆盖。保存位于“文件”菜单，也可按 `Ctrl/⌘ S`；生成 PRD 使用顶部“运行”菜单，已有正文时运行会进入修订。`Ctrl/⌘ Shift P` 打开命令搜索。“视图”菜单可切换侧边栏图标文字，隐藏时悬停查看提示，偏好会在刷新后保留。文件名显示在正文页签。

## 图文编辑与工作台布局

`PRD.md` 支持 Markdown 编辑、预览、分屏、标题、列表、表格和配图。正文工具栏的“原型图”打开原型设计，可导入 PNG/JPG/WebP 图片（原文件最多 8 MB），浏览器缩放到最长边 960 像素并转为 JPEG；透明部分转为白底。确认原型后，生成 PRD 时嵌入截图和说明。图文合计仍受正文 200,000 字符限制，超限会提示，不覆盖已有内容。图片随文档版本和导出文件保存。

正文工具栏的“流程图”按需打开顺序流程编辑器，每行一个节点，最多 20 个节点、每个节点 26 字；插入为 `nexus-flow` 代码块，在 Studio 和导出的 HTML 中渲染成 SVG。Markdown 导出保留可编辑代码块，其他 Markdown 阅读器不一定识别该格式。分支图、AI 生成图片与图像理解尚未接入；目前使用手动插图和顺序流程图。

文字模型请求会把内嵌图片编码替换成稳定短引用，避免图片字节占用大量 Token；不向模型传递图片像素。生成/修订后还原原图，遗漏的原文配图移到末尾“保留的配图与流程图”；没有返回流程图时保留原流程块。需要删除图片时请先在编辑器删除，再保存或发起修订。预览不执行原始 HTML 或外部 SVG 代码。

左侧 Agent 与 Skill 独立视图读取各自注册信息，可搜索和展开查看版本、能力与工具需求，运行后标记实际选用项。当前为注册清单查看，不提供插件安装、卸载或任意切换工作流角色；具体选择由后端编排器完成。保留菜单栏、左侧资源／能力管理、中间编辑区、右侧 AI 和底部状态栏。左侧默认显示项目资源，Agent 和 Skill 分别切换查看；初次空闲时不显示运行面板，执行后自动展开底部运行区域，可手动收起。底栏保留保存状态，流式内容、Flow 与 trace 集中在运行面板。材料、流程图、版本等辅助页面只在打开时增加一个可关闭的标签，关闭不会删除资料或停止服务端任务。

## 保存、冲突与恢复

“浏览器草稿”表示只保存在当前浏览器；“已保存”表示服务端保存成功。没有变化的重复保存不会额外创建版本。

新版草稿与最近 40 条澄清对话使用本标签页的 `sessionStorage`，刷新时可恢复；关闭标签页后不能当作持久备份。首次保存会把对话关联到文档 ID。AI 澄清请求携带最近 8 条有长度限制的对话及当前简报，尚未纳入服务端任务追溯。原型设计、正式生成、修订、评审仍使用持久任务与 SSE 输出。

文档 URL 中包含文档 ID，可直接收藏。文档库按更新时间显示已保存文档。点击历史版本预览，载入编辑区后再次保存，会形成新版本，不删除历史。

两页编辑同一份文档时，旧修订不能覆盖新修订；冲突会显示明确错误。本地编辑仍可导出或作为草稿恢复，再与服务器版本合并。

模型生成/评审期间锁定同一文档的写入。可以关闭页面再回来，任务继续运行。停止任务不会取消供应商已经接受的计算，也不保证免除费用，但会阻止后续阶段和迟到结果覆盖文档。

正文生成后立即保存；后续评审失败不丢失正文。服务重启将未完成任务标记为中断，释放文档锁，不自动重放付费模型调用。

## 数据与部署边界

SQLite 默认位于 `data/prd.sqlite3`，文档、版本和任务输出都包含原始材料。使用一个 API 进程（不要配置多个 Uvicorn workers 或多个实例共享该数据库）。当前任务调度器在进程内运行，启动恢复依赖这个单实例边界。

备份建议停服务后备份 `data` 目录，或使用 SQLite 在线备份 API；运行时不要只复制主数据库而漏掉 WAL。浏览器草稿是辅助恢复，不可替代数据库备份。

Docker 镜像安装 runtime 依赖，Compose 为 `/app/data` 配置 `prd-data` 持久卷；容器其余部分保持只读。当前改动未在本机执行 Docker 构建与 Compose 启动。

## API

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/v1/prd/configuration` | 查看模型是否配置；不会返回密钥 |
| GET | `/v1/prd/capabilities` | 读取实际 Agent / Skill 注册清单 |
| POST | `/v1/prd/assistant` | 需求澄清；支持空白简报，返回待用户应用的字段建议，不直接修改文档 |
| POST / GET | `/v1/prd/documents` | 创建简报 / 列出文档 |
| GET / PUT | `/v1/prd/documents/{id}` | 读取 / 保存；PUT 必须包含 expected_revision |
| GET | `/v1/prd/documents/{id}/versions` | 历史快照 |
| POST | `/v1/prd/documents/{id}/jobs` | 发起 generate / revise / review，返回 202 |
| GET | `/v1/prd/jobs/{id}` | 轮询实际任务进度与阶段输出 |
| GET | `/v1/prd/jobs/{id}/events?after=&limit=` | 分页读取单次任务的运行事件 |
| GET | `/v1/prd/jobs/{id}/stream` | 以 SSE 接收任务状态、当前阶段正文与可选思考过程 |
| POST | `/v1/prd/jobs/{id}/cancel` | 停止任务 |

`/v1/prd/runs` 仍是原有离线参考内核 API，供基线回归使用；新工作区不调用它。不要把其固定输出与参考质量分数当成真实写作结果。

## 验证方式与限制

```bash
python -m unittest discover -s tests -v
python -m ruff check .
python -m mypy packages/nexusos-python/src/nexusos benchmarks tests
python -m mkdocs build --strict
cd apps/studio
npm run typecheck
npm run build
```

受控模型测试验证上下文传递、路由、持久化、修订、失败和恢复，不评价真实模型写作质量。实际使用前，用 NexusOS 和另一个主题各生成一份文档，由作者对照简报逐项验收。

当前不提供联网事实核验、DOCX/PDF、自动版本差异或完整语义正确性保证。模型可能遗漏和误改内容，需要利用来源、版本和评审清单检查。用量为成功取得并经 Runtime 校验的响应统计；失败、截断和停止后的供应商计费以供应商记录为准。

## 全程追溯

通过“运行 → 运行面板与追溯”打开底部面板，在“历史追溯”中，选择任意历史任务，可检查本次输入快照、Agent/Skill 版本及选型依据、实际模型 messages、参数、响应、终止原因、Token、耗时，以及正文版本来源。展开事件可查看 trace_id/span_id 和内容哈希。

“文档时间线”也记录创建、人工编辑和版本恢复来源；任务与事件均支持分页。点击“导出追溯 JSON”可保存本次任务的证据包。导出包含原始材料与模型对话，应按原文的敏感程度保管。

新版右侧对话区（旧版页面顶部）的“显示思考过程”开关按任务生效。使用 DeepSeek 时，关闭会向模型发送 `thinking: {"type":"disabled"}`，只流式显示并保存正文；开启会发送 `thinking: {"type":"enabled"}`，并显示服务商返回的 `reasoning_content`。启用后的思考内容会保存在任务记录和追溯导出中。任务运行期间切换只改变当前页面的显示，并应用到下一次生成，不会改变已经发出的模型请求。

失败/停止任务提供“重新执行”和“继续执行”：重新执行保存当前输入并从头运行所选任务；继续执行复用已完成阶段，使用原始输入，从未完成处继续。两者都关联旧任务并保留独立 Trace。继续要求文档未修改且来源是最近任务，前端会显示不可继续的原因。旧任务没有记录的输入/调用会明确显示缺失，不补造历史。

详见[全程追溯问题与技术方案](../../development/runtime-issues/001-end-to-end-tracing.md)；后续长任务、限流、调度与记忆按[问题台账](../../development/critical-runtime-backlog.md)迭代。


## 失败后继续执行

底部运行面板的节点详情和历史追溯均有恢复入口。继续执行会复用分析及已完成写作片段；正文已保存而评审失败时只重新评审，不产生重复正文版本。服务重启后仍需手动选择继续，不自动发出模型请求。未完成阶段可能再次产生费用；继续执行不能修复模型配置或无限扩展输出上限。

安装依赖使用 `pip install -e ".[api,runtime]"`，其中包含 `langgraph-checkpoint-sqlite`。业务数据库旁新增 `.checkpoints` 文件（默认 `data/prd.sqlite3.checkpoints`），备份需包含两个数据库及各自 WAL，建议停服务后备份整个数据目录。详见 [检查点恢复方案](../../development/runtime-issues/003-checkpoint-recovery.md)。

## AI 对话附件与预览图细节

对话框左下角的回形针可选择多个文件，也可把文件拖入对话框。支持 Markdown、TXT、PNG、JPG、WebP；PDF、Word、PPT 需先转换为文本。文本会加入当前简报的参考材料，下一次澄清与生成可引用；图片压缩后加入原型设计；补充交互说明并确认后，生成 PRD 时会插入截图和说明。当前文字模型不会读取图片像素。

附件区显示实际工作区文件：点击文本附件打开材料页，点击原型图打开原型设计；文本附件可直接移除，原型页面在原型编辑器中删除。附件不是仅绑定一条消息的临时上传，清空对话不会清除它们。通过“文件 → 保存”持久化，未保存内容仍由标签页草稿辅助恢复。

一次最多选择 12 个文件。文本沿用每份 20,000 字符、合计 50,000 字符、最多 12 份的限制；图片最多 8 MB 原文件，原型最多 4 页、截图合计 140,000 字符，生成后图文合计最多 200,000 字符。批量文件全部校验成功后才一起加入；不支持的格式、空文本、读取失败或超限会显示具体错误，不部分覆盖工作区。读取附件期间锁定编辑和任务启动。

保留预览图中的分组序号，右侧移除重复的简报／正文上下文标签和切换按钮。`Ctrl/⌘ Enter` 可发送；对话新消息在接近对话底部时自动跟随，向上阅读后不会强制滚动。图中的未接入格式和外部能力不作为已实现按钮展示。

运行操作统一位于顶部“运行”菜单，不为单个运行按钮保留独立一行。生成／修订选择“运行 PRD 工作流”，评审与停止也在此菜单中；正文格式操作仍位于编辑器内部。


## 先设计原型，再编写 PRD

1. 在需求简报中填写产品和使用场景；右侧 AI 协助澄清。
2. 打开“原型设计”。已有原型图可导入 PNG/JPG/WebP，正文中旧配图可点击“纳入原型设计”；没有原型时，选择“根据简报生成原型”。
3. AI 生成可编辑线框页面。选择页面，点击按钮核对跳转；“编辑页面”可调整名称、说明、组件和跳转目标。也可在右侧对话提出原型修改要求，结果作为新的待确认设计保存。
4. 导入的原型图是静态图片，需要填写页面与交互说明。生成的线框同样需要核对规则和异常；界面不连接真实业务数据。
5. 选择“确认原型并生成截图”。确认所有页面后，通过文件菜单保存，或从运行菜单编写 PRD。需求发生修改会要求重新确认原型。
6. PRD 自动附带页面截图、对应页面说明及按钮跳转说明。修订会更新原型章节，避免重复堆图。原型和正文一起进入版本历史，Markdown / HTML 导出包含截图。

“运行”面板在启动任务时打开，展示整个阶段顺序。执行到哪个节点，哪个节点就呼吸高亮；点击节点弹出信息窗，查看状态、耗时、所选能力、模型输入输出及节点记录，“运行记录”显示中文时间线，“历史追溯”检查历次输入、模型调用和产物。面板可收起、展开高度，通过运行菜单再次打开；停止任务也仍在运行菜单中。对话区只负责交流与附件，不再重复显示运行输出。


流程画布支持拖动空白区域平移、滚轮或“＋／−”缩放、“适应画布”查看全图。节点通过曲线与连接点串联，拖动节点时连线跟随；移动仅调整显示位置，不改变真实执行顺序。信息窗可按 Escape、点击关闭或遮罩退出，关闭后焦点回到节点。查看详情会暂停跟随，重新开启“跟随进度”可继续定位当前执行节点。
