# Skill 路由与排序

## 1. 为什么不是一次向量检索

单一向量相似度无法表达租户策略、工具权限、成本、风险、历史成功率和延迟。NexusOS 将路由设计为多阶段漏斗：先缩小领域，再融合语义与词法信号，最后执行硬约束和预算选择。

```text
任务 -> 领域识别 -> 元数据过滤 -> 稠密/稀疏召回
     -> 融合排序 -> 策略过滤 -> 成本排序 -> 选择 1~5 个 Skill
```

## 2. 第一版评分

```text
最终分数 = 0.30 × 语义相关度
         + 0.15 × 关键词相关度
         + 0.15 × 领域相关度
         + 0.15 × 历史成功率
         + 0.10 × 能力匹配度
         + 0.10 × 成本得分
         + 0.05 × 延迟得分
```

本地参考实现使用确定性词法近似作为语义信号，便于离线测试。生产适配器可以把该信号替换为 Qdrant 的稠密与稀疏混合召回，领域与策略层保持不变。

## 3. 先过滤再选择

工具权限、领域白名单、最大成本和最大风险属于硬约束。未通过约束的候选不会进入最终选择器，不能依赖模型自行遵守。

## 4. 预算行为

Router 按得分顺序尝试装入 Skill，累计 `estimated_tokens` 不得超过请求预算。候选记录每个评分分量，便于运行详情页解释“为什么选择这个 Skill”。
