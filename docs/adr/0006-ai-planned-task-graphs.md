# ADR-0006：AI 自主规划任务 DAG 与受控流程并存

- 状态：已接受
- 日期：2026-09-11

## 背景

NexusOS 已有 `Goal`、`Task`、`TaskGraph`、拓扑层执行、Agent Resolver、Skill Router 和 Replanner，但当前 Planner 仍按 PRD 领域规则构造确定图，Studio 首页也只是按关键词识别已开放工具。随着研究、开发、数据、设计等能力加入，继续为每种请求手写一套固定顺序会削弱系统按任务组织 Agent、Skill、Tool 和界面的核心价值。

“AI 为任意任务生成 DAG”不能解释为模型获得任意执行权限。模型负责理解目标并提出任务、依赖和能力需求；NexusOS 负责验证、授权、预算、冻结版本和可靠执行。只有注册表与策略允许的图才成为可执行计划。

## 决策

NexusOS 将 **Intent-to-DAG（意图识别 → AI 自主规划任务 DAG）** 作为跨应用的 P0 核心能力，并长期提供两种规划模式：

1. `ai_dynamic`：面向通用任务。AI 可以在当前能力注册表和预算内提出非模板化 DAG，包括节点、依赖、并行关系、产物、验收条件和所需能力。确定性验证器通过后才允许执行。
2. `controlled_dynamic`：面向需要稳定流程的领域应用。应用提供版本化阶段库、允许的条件分支和依赖边界，系统仍按输入选择节点、Agent 和 Skill，但不允许模型任意改变关键质量门。Nexus PRD 默认使用并永久保留此选项。

用户选择、系统默认或策略强制的模式必须写入 Run 和 Plan 版本。高风险、合规或组织策略可以强制 `controlled_dynamic`；不得静默切换模式。通用 Studio 在 AI Planner 达到验收门后可以默认 `ai_dynamic`，但必须展示规划依据、图预览和不可执行原因。

## 强制边界

- AI 输出是 `PlanProposal`，不是可执行命令；不得携带代码、凭据或绕过 Tool Policy 的参数。
- 服务端验证任务 ID、节点数、依赖存在、无环、深度、扇出、能力可发现、Agent 可解析、数据分类、预算和高风险审批。
- 验证成功后生成不可变 `PlanVersion` 与摘要；Runtime 只执行该快照，不能让模型在执行中原地改图。
- Replan 创建新版本并记录替换关系，复用结果必须满足输入、能力、策略和产物摘要一致。
- 意图置信度不足、关键输入缺失、能力不存在或风险不可接受时进入澄清、等待审批或拒绝状态，不生成“看起来成功”的降级流程。
- 规划调用、原始提案、验证问题、最终 DAG、模式、模型、Prompt 版本、注册表快照、Token 和人工决定必须可追溯。

## PRD 模式

PRD 的 `controlled_dynamic` 继续由版本化阶段库保证需求、体验、技术、分段写作与独立评审等质量门；可按 action、复杂度、已有正文和原型状态选择需要的节点及并行关系。未来 PRD 也可显式试用 `ai_dynamic`，但不能删除受控模式或把实验模式静默设为既有文档的默认值。

## 后果

好处是新任务不必先复制一套固定工作流，系统能够真正按意图组合能力并暴露并行性；PRD 和高风险场景仍保留可预测、可回归的路径。代价是需要新的意图、提案、计划版本、验证和审批数据，需要对 Planner 本身做离线评测、对抗测试、成本限制和回放。

实现顺序、接口草案与验收标准见[AI 自主任务规划实施设计](../development/ai-dag-planning.md)。在这些准入完成前，项目状态不得宣称已经支持通用 AI 自主规划。
