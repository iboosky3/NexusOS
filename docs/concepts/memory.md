# Memory 设计

NexusOS 将记忆分为三类：

- Working Memory：当前运行的短期状态，适合 Redis 或运行时 Checkpoint。
- Episodic Memory：历史运行、选择与结果，适合 PostgreSQL 等持久化存储。
- Semantic Memory：可语义检索的知识与经验，适合 Qdrant 等向量存储。

领域层只依赖 `MemoryStore` 端口。内存实现用于测试与单机演示，不代表生产数据模型。任何检索结果仍需经过上下文预算与授权过滤。

每条 Memory 必须携带租户、来源 Run、来源类型、数据分类、创建时间和可选过期时间。检索时先按租户、允许分类和有效期过滤，再计算相关度；不能先做全局向量检索再在应用层丢弃，因为候选本身可能泄露跨租户信息。

当前 Orchestrator 的本地默认租户是 `local`，只为 CLI 和离线演示兼容。服务端租户必须来自鉴权中间件，不能从用户请求正文或模型输出读取。生产向量索引应使用租户分区或服务端过滤，并把原始 Memory ID 保留到上下文审计记录。
