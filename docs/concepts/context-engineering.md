# 上下文工程

## 1. 目标

上下文构建器不负责“把能找到的信息全部交给模型”，而是在固定预算中选择对当前任务最有价值的系统约束、任务信息、Skill、Memory、检索证据和工具 Schema，并为模型输出预留空间。

## 2. 默认比例

第一版默认按最大窗口分配：系统 8%、任务 8%、Skill 18%、Memory 10%、检索证据 26%、工具 8%、输出预留 22%。不同模型和工作流可以通过配置覆盖。

必要片段优先，然后按优先级、相关度和稳定顺序装入。普通片段无法容纳时被记录为省略；必要片段超过全局输入预算时直接失败，防止静默丢失安全约束。

分类比例是软上限，不是独立硬窗口。System 约束和当前 Task 属于必要片段时，可以借用其他尚未使用的输入分区，但仍必须满足“已消耗输入 + 输出预留不超过总窗口”。借用量写入 `BudgetReport.borrowed_tokens`，便于发现某类上下文长期挤占其他分区。

普通片段不能借用：超过本类比例或全局输入预算时直接裁剪并计入 `omitted_fragments`。这样既避免较长的真实用户需求在全局空间充足时被错误拒绝，也防止召回结果借“相关”为由吞掉输出空间。

## 3. Token 估算

离线参考实现不依赖模型厂商 tokenizer，对中文字符按约一个 Token、其他字符按约四字符一个 Token 进行保守估算。生产环境应使用模型适配器提供的准确计数，但仍返回统一预算报告。
