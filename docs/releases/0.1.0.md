# NexusOS v0.1.0 发布说明

发布日期：2026-09-09
发布类型：参考基线

v0.1.0 把 2026 年 5 月以来逐步形成的架构、契约、参考实现和验证工具整理为第一个可复现版本。它的目标是让后续开发拥有稳定起点，而不是用版本号掩盖尚未完成的生产集成。

## 本版本解决什么问题

当 Agent、Skill、模型和工具数量增长时，简单地把全部能力塞入提示词会快速耗尽上下文，也无法可靠回答“为什么这样路由、任务执行到哪里、失败能否恢复、数据是否越界”。本版本建立了以下最小闭环：

1. 用显式 Goal 和 TaskGraph 规划任务；
2. 按元数据检索 Skill，只为入选项渐进加载正文；
3. 在 Token、租户、数据分类和人工授权边界内执行；
4. 使用结构化质量结果决定完成、失败或有界重规划；
5. 通过 API、CLI、Studio 读模型和遥测解释运行过程。

## 可直接验证的能力

- 在 Python 3.12 环境运行 Nexus PRD 本地参考工作流；
- 通过 FastAPI 创建 Run，并查询稳定的摘要和详情投影；
- 使用 `nexus doctor --root .` 检查仓库资产、配置与可选工具链；
- 运行 Skill 路由回归、合成规模基准和 PRD 质量评估；
- 以 4 类 v1 JSON Schema 检查 Python、Go、Rust、TypeScript 边界；
- 阅读按时间追加的中文架构演进和实际问题解决记录。

## 契约兼容规则

v0.1 系列把 `contracts/` 下 Runtime、Router、MCP 和 A2A 的 v1 Schema 作为外部兼容边界。后续兼容版本可以增加可选字段，但不能直接删除字段、改名或把可选字段变为必填。发生破坏性变更时应创建 v2，并提供明确迁移路径。

## 从源码安装

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev,api,docs]"
nexus doctor --root .
python -m unittest discover -s tests -v
```

Windows PowerShell 使用 `.\\.venv\\Scripts\\Activate.ps1` 激活环境。Agent 与 Skill 当前仍是仓库级版本化资产，因此只安装 Wheel 后运行 PRD 命令时，必须通过 `--root` 指向同时交付的仓库资产目录。

## 封版验证

- Ruff 已完成源码内容的格式与 Lint 检查；当前宿主机对新文件的直接读取存在 NX-023 所述文件 I/O 环境限制；
- Mypy 检查 81 个源文件通过；
- 73 项 Python 测试通过；
- FastAPI TestClient 实际请求通过；
- 仓库 Schema、Manifest 和文档导航校验通过；
- MkDocs 严格模式构建通过；
- `nexusos-0.1.0` Wheel 构建通过。

## 已知限制

- Go、Rust 和 Node.js 源码未在当前开发机编译，需等待 CI 证据；
- Compose 拓扑未在当前开发机启动，数据库 RLS、消息系统和对象存储尚无真实联调证据；
- Local Runtime 使用确定性输出，Model Gateway 尚未连接真实供应商；
- 运行投影和 Memory 是进程内实现，重启后不恢复；
- MCP 与 A2A 只完成协议内核，没有真实远端互操作；
- Studio 只读，审批、重试和取消写操作尚未开放；
- 10,000 Skill 结果来自合成目录，不能外推为生产准确率或延迟承诺。
