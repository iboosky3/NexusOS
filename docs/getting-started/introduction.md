# 项目介绍

NexusOS 的中文名是“纽带”。它不是单个 Agent 产品，而是支撑多种 Agent 应用的通用基础设施。

## 要解决的问题

传统 Agent 应用常把全部工具和提示词直接注入模型上下文。当 Skill 数量达到数千甚至数万时，这种方法会导致 Token 成本失控、注意力稀释、选择准确率下降和响应延迟上升。

本项目的初始假设是：系统不应让一个模型记住全部能力，而应建立可检索的能力目录，并只在能力真正被选中后加载完整说明。

## 初始目标

1. 识别自然语言意图，由 AI 为任意已注册能力可承接的任务提出可解释 Task DAG，并经确定性校验后执行。
2. 从大规模 Skill 集合中检索少量候选。
3. 组织多个专业 Agent 协作。
4. 对上下文、成本、延迟和质量进行度量。
5. 通过 PRD 生成场景验证端到端闭环。

系统同时保留 `ai_dynamic` 和 `controlled_dynamic` 两种规划模式。前者不受单一领域模板限制，后者保留稳定阶段库和关键质量门；Nexus PRD 默认且永久保留受控动态选项。当前从首页输入目标即可进入编排页，调整确认后打开按任务筛选能力的通用工作台，PRD 内 AI 模式尚未开放；工具与审批等完整能力、路线与验收标准见[AI 自主任务规划实施设计](../development/ai-dag-planning.md#当前状态)。

## 非目标

当前阶段不自研大模型推理引擎，也不以替代数据库、消息总线或向量数据库为目标。这些能力通过清晰的端口接入。
