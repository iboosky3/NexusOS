# 策略与人工审批

NexusOS 使用服务端、拒绝优先的策略判断。模型提示词、Agent 声明或客户端请求都不能自行赋予权限。

每次资源动作至少携带经过认证的租户、主体、权限、角色、动作、资源租户、风险等级和数据分类。判断结果为：允许、拒绝或需要人工审批，并附带审计、审批记录和幂等键等执行义务。

判断顺序：

1. 主体身份完整。
2. 资源与主体属于同一租户。
3. 具备明确动作权限或资源通配权限。
4. 具备受限数据角色。
5. 风险未超过自动执行上限；超过时只有具备审批角色的流程可以进入等待审批。

本地规则引擎用于契约测试。生产环境计划使用 OPA 作为策略适配器，但必须返回相同 `PolicyDecision`，并保留服务端默认拒绝行为。

## 数据库租户上下文

每个 PostgreSQL 事务开始时，适配器使用参数化 `set_config` 写入 `nexus.tenant_id`。Row Level Security 对所有租户表强制执行 `USING` 与 `WITH CHECK`，即使应用查询遗漏过滤条件也不能跨租户读取或写入。

连接池归还连接前事务必须结束；禁止使用会话级 `SET`，避免租户上下文泄漏到下一位调用者。迁移与平台管理使用独立角色，不复用业务 API 凭据。
