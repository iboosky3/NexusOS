# 工作台插件与原型设计器

> **核心原则：保留稳定的软件工作台外壳，按用户任务装配需要的组件。每项主要操作只有一个入口，不为无关功能预留空面板。未来由 AI 分析任务并选择能力；当前 PRD 工作区通过显式注册装配插件。**

## 选型与扩展边界

原型设计器采用 [Puck](https://github.com/puckeditor/puck) 0.23.0（MIT），它是可嵌入 React / Next.js 的可视化组件编辑器，提供拖拽、嵌套布局、组件属性、图层以及撤销／重做。无需单独部署设计服务或开通云账户。[GrapesJS](https://grapesjs.com/docs/) 同样是通用开源页面编辑器；本项目优先复用 React 组件及声明式数据，因此选择 Puck。

`apps/studio/lib/workbench-extensions.ts` 定义通用 `ExtensionManifest`、`WorkbenchExtension<Props>` 与浏览器启用状态。插件声明 ID、版本、说明、开源来源、能力以及动态加载入口。`components/workbench/extension-browser.tsx` 统一提供搜索、打开、启用／禁用；侧边栏插件图标沿用文字显示／隐藏与悬停提示规则。

当前是**随应用发布、受信任的内置插件机制**，具有类似 VS Code 的入口和生命周期；并非 VS Code 扩展 API，也不能安装 `.vsix` 或任意远程 JavaScript。新增工具应注册新的 manifest 与加载器，通过类型化 props 接收宿主数据和回调，不直接操作 PRD API。网络市场、第三方安装隔离、能力权限执行以及 AI 自动装配尚未实现。

启用状态保存在 `nexus-workbench:disabled-extensions:v1`。禁用卸载编辑器，不删除设计或截图；重新启用加载原设计。插件管理在任务锁定时不可切换。实际编辑器和截图依赖在使用时加载，首页不挂载编辑器。

## 原型设计流程

原型设计器现以组件库、画布和右侧属性／图层组成三栏布局。组件库和属性面板均可从工具栏显隐；选中组件后右侧自动显示可编辑属性，AI 对话中也能看到选中组件的上下文。代码模式提供结构化 `prototype.json` 与画布分屏，点击画布组件会定位其 ID；修改代码须显式“应用代码”并通过设计数据校验。当前代码模式**不支持任意 HTML/JavaScript**，组件级 AI 修改与变更确认仍在迭代中。

1. 打开原型设计标签或插件时，工作台立即创建一个可编辑页面并显示组件库、画布和“保存设计方案”；也可以用 AI 工作流生成线框。编辑模式下左侧“网页组件”库始终显示，切换属性或图层时在组件库下方显示相应区域，用户仍可随时拖入新组件。
2. 从组件库拖入标题、文字、输入框、按钮、卡片、列表、分隔线、横向布局或双栏布局。将输入框和按钮拖入同一个横向布局即可并排，支持多个按钮、间距、对齐和换行；双栏支持调整左栏比例。切换“属性”修改名称、说明、按钮跳转，以及宽高（0 表示自动）、内外边距、字号、圆角、文字色和背景色（六位十六进制颜色，留空默认）。组件库与属性各自滚动。“图层”查看结构。当前使用网页流式布局，尺寸通过属性精确调整，不提供绝对坐标画布或拖动缩放手柄。
3. 选择桌面 960px 或手机 390px 画布。画布区域可滚动，不改变设计的实际尺寸。顶部箭头撤销／重做组件编辑。
4. 填写页面名称和交互说明，点击预览检查输入和按钮跳转。静态导入图保留图片与说明，不伪装成可编辑组件。
5. “截图并嵌入 PRD”先验证全部页面，使用相同的 React 配置渲染实际页面并在浏览器生成 JPEG，原子更新截图、确认状态和正文原型章节。若只准备运行，可以使用“确认原型并生成截图”。
6. “保存设计方案”或文件菜单保存。页面设计与自动生成的 Markdown 设计方案文档随简报写入数据库、版本及本地草稿，重新打开可以继续修改；新增修改取消原型确认，重新截图后更新 PRD。

原型设计是可选步骤。没有原型，或只有尚未确认、因需求变化而失效的原型草稿时，PRD 生成仍可直接运行；工作流不会把这些草稿作为需求输入，也不会嵌入草稿截图。只有摘要校验有效且已经确认的原型参与生成。用户可以随时返回原型页继续编辑草稿。

AI 生成的是受限线框组件。任务完成后原型标签默认进入编辑状态，Puck 将线框转换为同一份声明式设计数据，直接显示在拖拽画布中；用户无需先导出或重新创建页面。

截图章节沿用 `nexus-prototype:start/end` 标记，重复插入时替换旧章节，保留其他正文。正文只有原型章节时，运行仍触发首次 PRD 生成；后端生成和修订同样只保留一份原型章节。截图失败时不修改正文或确认状态。

`extensions/prototype-designer` 包含 manifest、编辑器、组件配置、预览及截图模块。宿主 `PrototypeEditor` 管理页面、确认与 PRD 插入，插件只负责页面设计。关闭右侧 AI 区可为画布腾出空间；从状态栏“AI 对话”恢复，内容和宽度保留。

## 数据与验证

局域网 HTTP 访问不依赖安全上下文专属的 `crypto.randomUUID` 或 `crypto.subtle`：组件 ID 使用 `getRandomValues` 生成 UUID，需求摘要在缺少 Web Crypto 摘要接口时通过惰性加载的 SHA-256 实现计算，保持与服务端相同的确认校验。

`PrototypePage.design` 保存 `{engine: "puck", version: 1, width, content}`，包含白名单 React 组件及受限属性，不保存 HTML、脚本或任意资源 URL。`Prototype.document` 是服务端校正的 Markdown 归档，记录页面、画布、组件、说明和跳转，随每个文档版本保存。服务端对版本、尺寸、组件类型、属性、ID、目标页面、深度及数量进行验证，并从设计重新计算 `elements` 和归档文档，防止页面摘要与设计脱节。

每个文档最多 4 个原型页面，每页最多 64 个组件、最多 4 层嵌套。组件名称 80 字、说明 200 字；页面说明 2,000 字。截图高度超过 5,000px 时要求拆页；截图按质量与尺寸压缩，每张设计截图不超过 35,000 字符、合计不超过 140,000 字符，文档正文上限保持 200,000 字符。复杂长页面应拆分，避免静默截掉页面内容。

工作流与澄清请求排除截图和 `design`，只传页面标题、描述、组件摘要和跳转；图片在模型完成后嵌入文档，编辑器数据不消耗模型上下文。AI 仍生成受限线框结构，用户可以在 Puck 中继续调整；不声称模型能读取截图像素或生成生产级前端代码。

集成测试 `tests/integration/test_prd_designer.py` 覆盖设计保存／读取、设计摘要、模型上下文隔离、生成配图保留、非法组件和错误跳转拒绝。浏览器验证覆盖拖拽、属性、撤销重做、画布尺寸、截图、重复嵌入、重新打开、插件开关和 AI 面板关闭／恢复。

## 模板上传

可复用 `TemplateUpload` 在“文档模板（可选）”中读取 Markdown / UTF-8 TXT / Word `.docx`。文件在浏览器本地解析，先预览，再由用户应用替换 `brief.template`。不加入参考材料列表；后续保存和模型生成沿用模板字段。

Markdown / TXT 保留文字目录；Word 使用 Mammoth（BSD-2-Clause）提取文字，不保留页眉、字体、图片或完整 Word 排版。文本最大 100 KB，Word 最大 5 MB，提取后最多 8,000 字符。空文件、不支持的格式和超限模板提示错误并保留原字段，不静默截断。尚不支持 PDF、旧 `.doc` 或扫描图片模板。
